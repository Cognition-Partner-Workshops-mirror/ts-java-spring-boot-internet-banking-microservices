# Remediation Roadmap — Internet Banking Microservices

## Phase 1 — Quick Wins (Effort = S)

These items are high-severity and low-effort. They can be addressed in targeted, focused changes.

| # | Gap | Severity | Devin Prompt |
|---|-----|----------|-------------|
| 1 | **Fix double-deduction bug in `utilPayment()`** — `availableBalance` is set to `actualBalance - amount` after `actualBalance` was already decremented | Critical | `Fix the balance calculation bug in core-banking-service TransactionService.utilPayment() and internalFundTransfer(). After subtracting from actualBalance, availableBalance is set to actualBalance.subtract(amount) again, causing a double deduction. The availableBalance should be set equal to the new actualBalance, not actualBalance minus amount again. Apply the same fix pattern in internalFundTransfer() for both from and to accounts. Add unit tests to verify correct balance after transfers.` |
| 2 | **Stop leaking stack traces in error responses** — generic `Exception` handler returns `"Exception occur inside API " + e` | Critical | `In all four services (core-banking-service, internet-banking-fund-transfer-service, internet-banking-user-service, internet-banking-utility-payment-service), update the GlobalExceptionHandler's generic Exception handler to return an ErrorResponse object with a generic message like "An internal error occurred" and log the full exception at ERROR level instead of including it in the response body. Return HTTP 500 instead of 400 for unhandled exceptions.` |
| 3 | **Add Bean Validation (`@Valid`) to all request bodies** | Critical | `Add Jakarta Bean Validation annotations to all request DTO classes across all services: @NotBlank on string fields (fromAccount, toAccount, account, email, identification, referenceNumber), @NotNull and @Positive on amount (BigDecimal) fields, @NotNull on providerId. Add @Valid annotation to all @RequestBody parameters in controllers. Add spring-boot-starter-validation dependency to each service's build.gradle. Add a MethodArgumentNotValidException handler in each GlobalExceptionHandler that returns 400 with field-level error details.` |
| 4 | **Return correct HTTP status codes** — `EntityNotFoundException` should return 404, generic exceptions should return 500 | High | `Update GlobalExceptionHandler in all four services: add a dedicated @ExceptionHandler for EntityNotFoundException (and its subclasses) that returns ResponseEntity.status(HttpStatus.NOT_FOUND). Change the generic Exception handler to return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR). Add handlers for InsufficientFundsException returning 422 (UNPROCESSABLE_ENTITY). Ensure all handlers return a consistent ErrorResponse{code, message} object.` |
| 5 | **Return pagination metadata instead of raw List** | High | `In core-banking-service UserController.readUsers(), internet-banking-fund-transfer-service FundTransferController.readFundTransfers(), and internet-banking-utility-payment-service UtilityPaymentController.readPayments(): change the service methods to return Page<T> (or a custom PageResponse DTO with content, totalElements, totalPages, page, size) instead of converting to List and discarding page metadata. Update the corresponding service classes to return the Page object directly.` |
| 6 | **Add Zipkin tracing to Core Banking Service** | High | `Add the following dependencies to core-banking-service/build.gradle: 'io.micrometer:micrometer-tracing-bridge-brave', 'io.zipkin.reporter2:zipkin-reporter-brave', 'io.github.openfeign:feign-micrometer'. This aligns it with the other services that already have these dependencies and ensures end-to-end distributed tracing through Zipkin.` |
| 7 | **Add Feign client timeout configuration** | High | `Add Feign client timeout configuration to each service that uses Feign (fund-transfer, user, utility-payment). In each service's application.yml (or the centralized config repo), add: spring.cloud.openfeign.client.config.default.connect-timeout=5000, spring.cloud.openfeign.client.config.default.read-timeout=10000. This prevents indefinite blocking when Core Banking is slow.` |
| 8 | **Add Spring Retry to Feign clients** | High | `Add 'org.springframework.retry:spring-retry' and 'org.springframework:spring-aspects' dependencies to fund-transfer, user, and utility-payment services. Enable retry with @EnableRetry on each main application class. Configure Feign retry in application.yml: spring.cloud.openfeign.client.config.default.retryer with maxAttempts=3 and backoff. Alternatively, add a Retryer bean in each CustomFeignClientConfiguration.` |
| 9 | **Fix non-RESTful endpoint naming in User Service** | Medium | `Rename endpoints in internet-banking-user-service UserController: change POST /api/v1/bank-users/register to POST /api/v1/bank-users (standard REST collection POST for creation), change PATCH /api/v1/bank-users/update/{id} to PATCH /api/v1/bank-users/{id}. Update the API Gateway security config to match the new registration path: change the permitAll path from /user/api/v1/bank-users/register to /user/api/v1/bank-users for POST method only.` |
| 10 | **Return 201 Created for POST resource-creation endpoints** | Medium | `In internet-banking-user-service UserController.createUser(), internet-banking-fund-transfer-service FundTransferController.sendFundTransfer(), and internet-banking-utility-payment-service UtilityPaymentController.processPayment(): change ResponseEntity.ok() to ResponseEntity.status(HttpStatus.CREATED).body(). This follows REST conventions for resource creation.` |
| 11 | **Add Prometheus metrics endpoint** | Medium | `Add 'io.micrometer:micrometer-registry-prometheus' dependency to all service build.gradle files. Ensure management.endpoints.web.exposure.include=health,info,prometheus is set in the application configuration. This enables Prometheus-compatible metrics scraping at /actuator/prometheus.` |
| 12 | **Fix Keycloak singleton thread-safety** | Medium | `In internet-banking-user-service KeycloakProperties.java, make the getInstance() method thread-safe. Either synchronize the method, use double-checked locking with volatile, or use a holder pattern. The simplest fix: make keycloakInstance volatile and synchronize the null-check block.` |
| 13 | **Move secrets out of docker-compose.yml** | Medium | `Replace hard-coded passwords in docker-compose/docker-compose.yml with environment variable references. Change MYSQL_ROOT_PASSWORD, KEYCLOAK_ADMIN_PASSWORD, KC_DB_PASSWORD to use ${MYSQL_ROOT_PASSWORD}, ${KEYCLOAK_ADMIN_PASSWORD}, etc. Create a docker-compose/.env.example file documenting the required variables. Add docker-compose/.env to .gitignore.` |
| 14 | **Add rate limiting to API Gateway** | Medium | `Add Spring Cloud Gateway RequestRateLimiter filter. Add 'org.springframework.boot:spring-boot-starter-data-redis-reactive' dependency to the gateway's build.gradle. Configure a RequestRateLimiterGatewayFilterFactory with RedisRateLimiter in the gateway route configuration. Set sensible defaults (e.g., replenishRate=10, burstCapacity=20). Add a Redis container to docker-compose.yml.` |
| 15 | **Fix parameterized logging in CustomFeignErrorDecoder** | Low | `In internet-banking-user-service CustomFeignErrorDecoder.java, change log.error("IO Exception..." + e) to log.error("IO Exception on reading exception message feign client", e) using parameterized logging. This applies to lines 32 and 39.` |
| 16 | **Add type parameters to raw ResponseEntity** | Low | `Add type parameters to all raw ResponseEntity declarations in controllers across all services. For example: ResponseEntity<BankAccount> getBankAccount(), ResponseEntity<FundTransferResponse> fundTransfer(), etc. This improves compile-time type safety and OpenAPI documentation accuracy.` |
| 17 | **Mask sensitive data in log statements** | Medium | `Review all log.info() calls that log request.toString() or DTO toString() output in controllers and services. Replace with selective field logging that excludes account numbers, amounts, and passwords. For example, log only transaction IDs or use a sanitized toString(). Affected files: FundTransferController.java, UtilityPaymentService.java, UserController.java.` |

## Phase 2 — Important (Effort = M)

These items are significant improvements that require moderate refactoring or new infrastructure.

| # | Gap | Severity | Devin Prompt |
|---|-----|----------|-------------|
| 18 | **Add circuit breakers with Resilience4j** | Critical | `Add 'org.springframework.cloud:spring-cloud-starter-circuitbreaker-resilience4j' dependency to fund-transfer, user, and utility-payment services. Configure circuit breakers for each Feign client with: failureRateThreshold=50, waitDurationInOpenState=30s, slidingWindowSize=10. Add fallback methods that return appropriate error responses and update local entity status to FAILED. Configure in application.yml under resilience4j.circuitbreaker.instances.` |
| 19 | **Add fallback handling for Feign failures** | High | `In FundTransferService.fundTransfer() and UtilityPaymentService.utilPayment(), wrap the Feign client call in a try-catch. On failure: update the local entity status to FAILED, log the error, and return a response indicating the failure. Consider adding a @FeignClient fallbackFactory for each Feign client that returns meaningful error responses instead of propagating exceptions.` |
| 20 | **Add idempotency keys to fund transfer and payment endpoints** | High | `Add an idempotencyKey field to FundTransferRequest and UtilityPaymentRequest. In each service, before processing: check if a record with the same idempotency key already exists in the repository (add a findByIdempotencyKey method). If found, return the existing response. If not, proceed with processing and persist the key. Add a unique constraint on the idempotency_key column in each entity table.` |
| 21 | **Secure internal services with service-to-service auth** | High | `Add Spring Security to core-banking-service. Configure it as an OAuth2 resource server (same Keycloak JWT validation as the gateway) OR implement a simpler approach: add a shared API key header check. The Feign clients in fund-transfer, user, and utility-payment services should include an Authorization header via a RequestInterceptor. This prevents direct unauthorized access to Core Banking endpoints.` |
| 22 | **Encrypt secrets in Spring Cloud Config** | High | `Enable Spring Cloud Config Server encryption. Generate a symmetric key and set encrypt.key in the config server's configuration. Encrypt sensitive properties (database passwords, Keycloak client-secret) using the /encrypt endpoint and store them as {cipher}... values in the Git config repo. This prevents secrets from being stored in plain text in the configuration repository.` |
| 23 | **Add structured JSON logging** | Medium | `Add 'net.logstash.logback:logstash-logback-encoder' to each service's build.gradle. Create a logback-spring.xml in each service's src/main/resources/ that configures LogstashEncoder for JSON output. Include traceId, spanId, and service name in the JSON structure. This enables log aggregation with ELK/Loki.` |
| 24 | **Add custom health indicators** | Medium | `Create HealthIndicator beans in each service: a MySQLHealthIndicator that checks database connectivity beyond the auto-configured DataSource health, a KeycloakHealthIndicator in the user service that pings the Keycloak server, and a CoreBankingHealthIndicator in fund-transfer and utility-payment services that checks the Core Banking /actuator/health endpoint via Feign.` |
| 25 | **Add bulkhead isolation** | Medium | `Add Resilience4j bulkhead configuration to isolate Feign client thread pools. Configure resilience4j.bulkhead.instances for each Feign client with maxConcurrentCalls=10 and maxWaitDuration=500ms. This prevents a slow Core Banking response from consuming all threads.` |
| 26 | **Add controller-level tests** | Medium | `Create @WebMvcTest test classes for each controller: AccountControllerTest, TransactionControllerTest in core-banking-service; FundTransferControllerTest in fund-transfer; UserControllerTest in user-service; UtilityPaymentControllerTest in utility-payment. Mock the service layer and verify HTTP status codes, response bodies, and validation error handling. Use MockMvc for assertions.` |
